# REVO — ملخص المشروع: القيمة، المستفيد، التقنيات، وخطوات التنفيذ

## 1) الـ Value Proposition (القيمة المقدمة)
REVO هي لعبة نجاة استعمارية مريخية بأسلوب بكسل ريترو للاطفال (8–12 سنة)، بتعلّمهم
التفكير العلمي وإدارة الموارد تحت الضغط — مستوحاة من قصص حقيقية (مثل عاصفة التراب
التي أنهت مهمة Opportunity عام 2018).

- **قرارك يغيّر كل حاجة**: كل كارت فيه trade-off حقيقي (بطارية/أكسجين/درع/مشاعر)،
  والناتج والستيكِر والصوت يتغيروا حسب اختيارك — مش مجرد أزرار.
- **عالم حي يحس بيك**: عاصفة تراب ثلاثية المراحل (اقتراب → ذروة → انقشاع) مربوطة
  بسياق القصة وشدة القرار، مع رياح وموسيقى ديناميكية وهبّات متزامنة بصريًا وصوتيًا.
- **شخصية بتتكلم معاك فعلاً**: 188 سطر صوتي مؤدي بالكامل لـ N.E.I.L. — مش تكتيك،
  صوت بيريوى كلام الشاشة حرفيًا (مطابقة نصية دقيقة، وميزة Read Aloud لكل طفل).
- **مكافأة لكل إنجاز**: ألبوم 39 ستيكر مع احتفال Confetti + Collect-Burst عند كل فتح.
- **Kid Mode آمن**: وضع مخفّف للاصغر سنًا + "محاكاة تدريبية — قاعدة خيالية" لتوضيح الإطار.

## 2) مين المستفيد من الحل
- **الأطفال (8–12)**: تعلّم تجربة-بالفعل للموارد والقرارات (Science-by-play) بدل المحاضرة.
- **الأولياء والمعلمين**: محتوى علمي حقيقي (Jezero Crater، Opportunity، الطاقة الشمسية)
  بلغتهم، بدون إعلانات، بدون شراء داخل اللعبة، أوفلاين بعد أول تحميل، ويعمل على المتصفح أي جهاز.
- **صناع ألعاب التعليم (EdTech)**: نموذج قابل للتوسعة — نظام Content مفصول عن المحرك
  (مهام/أزمات/كروت/صوت في ملفات بيانات)، يسهل إضافة سيناريوهات جديدة بدون لمس المنطق.

## 3) إيه اللي بيميزنا عن الحلول الموجودة
| المنافس/النمط | الثغرة | اللي بنعمله مختلف |
|---|---|---|
| ألعاب النرد/القرارات النصية (Soda Dropout, Reigns-like) | عالم ساكن، بدون حضور بصري للخطر | عاصفة تتصاعد مع مراحل القرار وتهدأ بعد الانقشاع، نفس الـ level يقود الجرافيك والصوت |
| ألعاب إدارة موارد للبالغين (Frostpunk-like) | قاسية ومعقدة على الطفل | نفس الـ trade-off mechanic مبسوط في 3 كروت ملونة + شرح بصري للتكلفة |
| ألعاب أطفال تعليمية (Toca/LEGO style) | لا تحدي، لا عواقب | 30 Sol حقيقية، موارد بتنقص، ونهايات متعددة تحكي نتيجة قراراتك |
| ألعاب ويب بدون تعلّم صوتي | القراءة حاجز للطفل الصغير | تطابق صوت↔نص 100% + Read Aloud + نبرة شعورية لكل لحظة (هدوء/ذعر/احتفال) |
| روم-فورك | مؤثرات مش مسموعة أو صوت من غير شكل | التزامن الكامل: الهبة = Curl على الشاشة + Whoosh + هزة خفيفة + طنين الرياح |

**فكرة للتوسعة**: نفس الـ Storm Engine (مكوّن واحد بخاصية `level` واحدة) قابل لإعادة
التنفيذ لأي خطر طبيعي (بركان، عاصفة ثلجية على قمر)، وكل خطر يجرى له Crisis Card Set +
Sticker Set + Voice Arc — منظومة محتوى قابلة للتكرار بمحتوى جديد بدون كود جديد.

## 4) التقنيات والأدوات اللي استخدمناها
- **محرك اللعبة**: TypeScript + React + Vite، رسم DOM/canvas طبقات، اختبارات Vitest (57/57).
- **الصوت**: TTS بتوليد AI (صوت N.E.I.L. واحد ثابت لكل الأسطر) + لاعب صوتي Manifest-driven
  بمطابقة نصية دقيقة؛ موسيقى توليد AI بحلقات؛ 60+ SFX مُولّدة إجرائيًا بـ NumPy/FFmpeg
  (wave synthesis ثم MP3 بمعدلات مختلفة)؛ قنوات (music / VO / SFX / wind) مع Ducking ذكي
  وسياسة autoplay محترمة (أول gesture).
- **الجرافيك**: شرائح PixelLab spritesheets المقطّعة بـ Python/Pillow، مكتبة pixelfx
  مفتوحة المصدر (MIT) لـ Tornado/Fog/Confetti/Collect-Burst معاد تلوينها للبالتة المريخية،
  ومحرك عاصفة Canvas بـ Parallax + Easing أسّي (τ≈2.5–3.5s) بين المراحل.
- **الخط/الواجهة**: خط بكسل، HUD مقاسات ملونة، Kid Mode toggle، ألبوم ستيكرز.
- **Deploy**: GitHub (فرع `main`) + Vercel (مشروع Git-linked — بناء تلقائي
  مع كل Push على فرع الإنتاج) — إعداد Vite: `dist/` ثابت، SPA fallback.

## 5) خطوات التنفيذ (Timeline مختصر)
1. تحليل الكود: خريطة الملفات (engine/rules/content/screens) والتزام عدم لمس منطق اللعبة.
2. Voice audit + اختيار صوت N.E.I.L. من مرشحين ثم اعتماد صوت واحد ثابت.
3. توليد 188 سطر + 4 حلقات موسيقى + 60+ SFX إجرائية + تحويل MP3 ومانيفيست أوتوماتيك.
4. إعادة بناء لاعب الصوت (segment-chained exact matching) + قنوات وموسيقى ديناميكية.
5. أصول العاصفة: تقطيع الشيتات + رندر pixelfx + محرك DustStorm بطبقات ومراحل.
6. ربط العاصفة بأزمة c1 والشاشة والقرار، وربط الاستيكرز بالاحتفال، وLogo intro.
7. تحقق حي: لعب c1 كاملة في المتصفح، بروب حركة/صوت/طلبات، ثم Build + اختبارات + توثيق.
8. النشر: فرع جديد على GitHub → ربط Vercel → Deploy على فرع الإنتاج.

## 6) حالات النشر الحالية
- الفرع `main` هو فرع الإنتاج على Vercel، وبداخله حزمة التسليم كاملة في `public/demo/`.
- انتظار موافقة صلاحية الكتابة على GitHub App ثم Push → ثم مشروع Vercel مرتبط بالنفرع.

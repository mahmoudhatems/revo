# REVO: Scenario vs. Data Conflict Report

Sources compared:

- **MD**: `Mars Survival Game — Kid Edition.md`, the final approved scenario and primary authority.
- **JSON**: `data final.zip`, 11 files, copied unchanged to `src/game/data/`.
- **APP**: the existing implementation (`src/game/*`, `src/ui/*`).

Status key:

- **RESOLVED-MD**: the MD (or the owner's approved decision list) is explicit. The app follows the MD, and the JSON value is kept but overridden in `src/game/data/index.ts`.
- **OPEN**: needs an owner decision. The app keeps the behaviour noted under "Current app" until a decision is made.
- **GAP**: the value or asset does not exist in any source.

## 4. Missing external data and assets (GAP)

- `final_marstrek_terrain.json`: missing. The map is **not** verified against NASA Mars Trek. To validate it, we need a 5×5 tile-type grid in (col,row) and confirmation of the crater positions and of the (3,0)/(3,3) ice and (2,2)/(3,2) mountain tiles.
- `final_donki.json`: missing. Event classes are known (M1.2 hazard 2, X2.1 hazard 3 CME, C3.4 hazard 1), but **no original event dates** are given. The UI labels them "archived NASA data" and shows no date.
- `final_csa_food.json`: missing. The catalog embedded in the Mission 5 file is used.
- Data references: the JSON `data_sources` give dataset **names only**, with no URLs, DOIs or dates. Facts are labelled by dataset name only.
- Voice-over audio: none supplied. The app looks for `public/assets/revo/vo/<line-id>.mp3`, falls back to the browser's speech synthesis, and is silent if neither is available.
- Sticker artwork: none supplied. Stickers are drawn with the existing pixel icon set.
